# 개인 프로필: 마인드맵 → 모티브 → 오너먼트 리서치 작업 기록

작성일: 2026-11-24  
보완: 같은 날 사용자 지시·수업 HTML·실제 실행 기록을 대조해 반복 절차와 이번 회차의 선택을 구분했다.  
목적: 다음 대화의 에이전트가 이 파일을 읽고, 사용자의 의도와 기존 결과를 유지하면서 같은 조사 과정을 반복할 수 있도록 한다.

## 1. 다음 작업을 시작할 때 먼저 읽을 내용

- 사용자가 ‘기다려’, ‘일단 확인’, ‘계획 먼저’라고 지정한 범위를 따른다. ‘시작해’라고 하면 직전에 설명하고 승인받은 범위를 끝까지 수행한다. 모든 단계에 별도 확인이 필요하다는 고정 규칙으로 해석하지 않는다.
- 마인드맵은 한 번 만들고 끝나는 산출물이 아니다. **새 키워드를 찾을 때마다 기존 마인드맵을 확장하거나 새로운 마인드맵을 만든다.** 기존 원본 취향과 과거 버전은 출발 자료로 보존한다.
- 이번 조사에 적용한 키워드는 **견고함, 중첩, 리듬, 개방감, 빛의 여운**이다. 영구적으로 고정된 목록이 아니며, 다음 탐색에서는 확장·신규 마인드맵을 바탕으로 다시 5개를 선정한다.
- `모티브 1`과 `오너먼트 1`에는 이 키워드로 조사한 이미지가 각각 10개씩 들어 있다.
- 강아지 관련 섹션은 사용자가 설명한 방법을 이해하기 위한 사례이자 별도로 수행한 실습이다. 개인 프로필의 주제를 강아지로 바꾸라는 의미가 아니다.
- 원본 취향, 에이전트가 확장한 연상, 최종적으로 채택한 키워드를 구별한다. 취향에 대한 해석을 사용자가 직접 말한 사실처럼 쓰지 않는다.

| --- | --- | --- |

| 수업 HTML | 자기 분석부터 프로필 시안·컬러·로고까지의 학습 과정 | 전체 흐름과 산출물 기준. 이번 작업의 완료 범위와 분리 |

HTML을 읽거나 보드를 확인했다는 사실만으로 사용자의 취향, 콘셉트, 디자인이 최종 확정되었다고 쓰지 않는다. 이번 5개 키워드는 사용자가 후속 조사를 진행하도록 지정한 작업 기준이며, 영구적인 개인 정체성의 확정은 아니다.

## 2. 핵심: 사용자가 말한 ‘3차원적으로 연결하기’

여기서 ‘3차원적’이라는 말은 입체 효과나 3D 렌더링을 뜻하지 않는다. 주제에서 **경험·촉감·상황·감정·관계**로 생각을 확장하고, 이를 다른 소재와 공간의 모습에 연결하는 방법이다.

기본 흐름:

> 주제 또는 취향 → 구체적인 경험과 상황 → 감각·감정·관계 → 사진에서 발견한 시각적 단서 → 모티브 → 형상화할 조형 특징 → 오너먼트

이 흐름은 설명을 추적하기 위한 틀이다. 매번 모든 중간 단계를 억지로 만들어 길게 쓰라는 뜻은 아니다. 촉감의 직접 연결도, 상황을 거친 감정의 연결도 가능하다. 중요한 것은 연결 근거가 사진에서 확인되고 원래 주제와 이어지는가이다.

### 사용자가 직접 설명한 강아지 사례

1. **털과 척추뼈의 감각**
   - 강아지 → 쓰다듬는 경험 → 손끝에 느껴지는 털결과 척추뼈 → 사진의 표면 질감과 굴곡.
   - 사진에 실제 강아지나 뼈가 있어야 하는 것은 아니다.
2. **혼자 남겨진 상황과 쓸쓸함**
   - 강아지 → 주인이 집을 나감 → 혼자 남는 쓸쓸함 → 거대한 블록 공간에 홀로 있는 작은 사람.
   - 같은 사진도 주제와 연결하는 관찰과 설명에 따라 모티브가 된다.
3. **모티브에서 오너먼트로 발전**
   - 쓰다듬을 때 느끼는 척추뼈 → Pinterest에서 척추뼈 검색 → 관련 추천을 따라 탐색 → 중심축·마디의 반복·휘어짐·양옆으로 뻗는 구조를 가진 장식 이미지.
   - 뼈 그림 자체를 찾는 데서 멈추지 않고, 그 구조를 다른 선과 문양으로 표현한 사례까지 발전시킨다.

### 조사할 때 스스로 확인할 질문

- 이 주제와 관련해 어떤 행동, 촉감, 장면, 관계가 떠오르는가?
- 사진의 어느 부분이 그 경험과 이어지는가?
- 색이나 분위기 외에 선·형태·밀도·간격·여백·크기 대비로 설명할 수 있는가?
- 중간 연결을 생략한 억지 연상은 아닌가?
- 최종 오너먼트에서 원래 모티브의 어떤 특징이 남아 있는가?

‘견고함 → 기둥’, ‘리듬 → 반복 무늬’처럼 단어를 바로 대응시키는 데서 끝내지 않는다. 예를 들어 ‘꾸준한 운동 → 작은 반복의 축적 → 가는 금속선이 수없이 감긴 모습 → 선들이 서로 맞물리는 매듭’처럼 연결을 설명한다.

### 혼동하기 쉬운 네 가지 산출물

| 산출물 | 역할 | 이번 사례 |
| --- | --- | --- |
| 시각 키워드 | 이번에 탐색할 주제·개념 | 강아지, 견고함, 중첩 등 |
| 모티브 이미지 | 주제와 연결되는 감각·상황·형태의 단서 | 표면의 굴곡, 홀로 있는 사람, 겹친 종이 |
| 오너먼트 레퍼런스 | 그 단서를 장식용 조형으로 표현한 사례 | 마디가 반복되는 곡선, 맞물린 선, 겹친 경계 |
| 적용 디자인 레퍼런스 | 조형을 타이포그래피·레이아웃에 적용한 완성 사례 | 포스터, 배너, 편집물, 패키지, 프로필 화면 |

이번에 오너먼트 보드를 채운 것과 HTML의 최종 적용 디자인 레퍼런스 선정을 같은 완료 상태로 취급하지 않는다. 실제 프로필이나 표지로 발전시킬 때는 조형이 사용된 디자인 사례와 타이틀 표현을 추가로 비교해야 한다.

### 좋아하는 것

- 영화·영화 보기: 해리포터, 마블 시네마틱, 반지의 제왕, 어바웃 타임, 인터스텔라, 라라랜드.

## 5. 이번에 적용한 시각 키워드 5개

| 키워드 | 마인드맵 출발점 | 경험·감정의 확장 | 조사할 조형 특징 |
| --- | --- | --- | --- |
| 견고함 | 헬스·운동, 책임감 없는 것을 싫어함 | 작은 반복이 쌓여 버티는 힘과 서로 지지하는 신뢰 | 밀집한 평행선, 교차, 결속 |
| 중첩 | 판타지 영화·독서, 세계에 몰입하는 경험 | 한 장면 뒤에 이야기와 기억이 포개지는 깊이 | 겹친 윤곽, 층, 안쪽으로 이어지는 여백 |
| 리듬 | 음악 듣기, 헬스·야구·축구 | 반복 속에서 고조되고 쉬어 가는 호흡과 박자 | 선의 간격, 진폭, 반복의 강약 |
| 개방감 | 간섭·강요를 싫어함, 자율성과 선택 | 경계는 있어도 숨 쉴 틈과 나갈 방향이 남는 상태 | 열린 끝, 빈 중심, 자유로운 흐름 |
| 빛의 여운 | 어바웃 타임·라라랜드·인터스텔라 | 장면이 끝나도 마음에 남는 시간과 감정의 흔적 | 흐려진 윤곽, 밝기의 감쇠, 길게 남은 선 |

이 연결은 개인적 해석이다. 영화·음악 취향만으로 성격을 단정하거나 보편적 심리학 사실처럼 설명하지 않는다.

### 키워드 탐색은 반복한다

사용자가 추가로 명확히 한 원칙: 마인드맵을 지금 상태에서 완료·고정하지 않고, 키워드를 찾고 싶을 때마다 확장하거나 새로 만든다.

> 원본 취향과 새로운 관찰 → 기존 마인드맵 확장 또는 신규 마인드맵 → 시각 키워드 5개 재선정 → 모티브 → 오너먼트 → 검토 → 필요하면 다시 마인드맵으로 돌아가기

- 매 탐색 회차의 키워드는 5개지만, 모든 회차가 같은 5개일 필요는 없다.
- 기존 가지에서 새로운 경험·상황·감각을 연결해도 되고, 다른 관점으로 마인드맵 전체를 새로 구성해도 된다.
- 새 회차에는 회차나 날짜를 표시해 어떤 마인드맵에서 어떤 키워드와 모티브가 나왔는지 추적한다.
- 이번 키워드와 모티브 보드는 이전 회차의 기록으로 남긴다. 새로운 조사라고 기존 결과를 자동으로 덮어쓰지 않는다.
- HTML의 취향 검토·키워드 수정 원칙에 사용자의 이 반복 지시를 함께 적용한다.

### 확장·신규 제작·재선정의 판단 기준

- 기존 가지가 유용하고 새 경험을 연결할 공간이 있으면 해당 가지에서 확장한다.
- 기존 분류가 사고를 제한하거나 다른 관점의 주제를 탐색하려면 새 마인드맵을 만든다.
- 출발 취향을 원하는 결과에 맞춰 바꾸지 않는다. 새로 떠올린 해석을 원본처럼 추가하지 않는다.
- ‘무엇을 좋아하는가’에서 ‘어떤 순간이 좋은가’, ‘손·귀·몸으로 어떻게 느끼는가’, ‘혼자 또는 타인과 어떤 관계인가’, ‘무엇과 대비되는가’로 가지를 확장할 수 있다.
- 이미지를 찾기 어렵거나, 후보끼리 같은 의미·같은 모양으로 수렴하거나, 사진과의 연결을 설명하기 어렵다면 가지를 더 확장하고 키워드를 재선정한다.
- 이미지 조사 중 새로운 연결이 보이면 마인드맵으로 돌아가 추가해도 된다. 조사 순서를 일방향으로만 고정하지 않는다.

### 키워드 선정 기준

- 회차마다 후보를 넓게 만든 뒤 시각화 가능한 5개를 선정하고 이유를 적는다.
- 키워드는 반드시 성격 형용사나 추상 개념일 필요가 없다. HTML의 예시처럼 식물·강아지·산책 같은 구체적 주제도 가능하다.
- 각 키워드가 어느 원본 항목과 확장 가지에서 나왔는지 추적할 수 있어야 한다.
- 사진·질감·공간·형태로 연결할 수 있어야 하며, 5개가 서로 다른 탐색 방향을 가져야 한다.
- 기존 오너먼트에 맞추려고 키워드를 거꾸로 끼워 맞추지 않는다.

과거 보드에 적힌 `빈티지·남성적인·직선적인·메탈릭·고전` 및 수업 정리 문서의 `차분함·정돈됨·지적인 인상·여유·포근함`은 별도의 과거 목록이다. 사용자가 이번에 반복하도록 지정한 목록은 위 5개다.

## 6. 반복 가능한 작업 절차

### 단계 A. 범위와 원본 확인

1. 이 문서와 사용자의 최신 지시를 읽는다.
2. 대상 FigJam과 지정 섹션을 확인한다. 기존 결과를 덮어쓸지, 추가할지 문맥을 확인한다.
3. 이미 선택한 키워드로 모티브 조사만 이어가는 회차라면 해당 마인드맵을 참조한다. **새 키워드 탐색을 시작하는 회차라면 기존 마인드맵을 확장하거나 새 마인드맵을 제작한다.** 원본과 확장 연상은 구별한다.
4. 확장·신규 마인드맵에서 시각화 가능한 키워드 5개를 새로 선정한다. 특정 키워드로 계속하라는 최신 지시가 있으면 그 범위를 따른다. 과거 5개를 자동으로 고정하지 않는다.

이번 회차 시작 전에는 다음만 짧게 정리하면 된다: `시작 단계 / 사용할 마인드맵 / 키워드 5개 / 탭 제한 / 후보 수 / 대상 섹션 / 완료 범위`. 이미 정해진 조건을 매번 다시 질문하지 않는다.

### 단계 B. Unsplash에서 모티브 조사

1. Playwright MCP 브라우저의 탭 목록을 확인하고 Unsplash 탭으로 전환한다.
2. 이용할 카테고리는 다음 두 곳이다.
   - [텍스처](https://unsplash.com/ko/t/textures-patterns)
   - [건축학](https://unsplash.com/ko/t/architecture-interior)
3. 탭 안에서 스크롤하며 후보를 살핀다. 전체 검색 결과를 보고 해당 탭에서 찾았다고 기록하지 않는다.
4. 각 키워드에 대해 텍스처 1장, 건축학 1장을 선정한다. 이번 기준은 총 10장이다.
5. 주제·키워드 → 경험·감정 → 사진 속 구체적 단서의 연결을 직접 설명한다.
6. 실제 이미지를 크게 확인한다. 대체 텍스트만 읽고 사진을 해석하지 않는다. 로딩 전 흐린 미리보기를 완성된 사진으로 판단하지 않는다.
7. 사진의 원본 페이지 URL, 실제 이미지 URL, 카테고리, 제목, 선정 이유를 함께 확보한다.

건축학 탭만 사용하라는 지시가 있으면 그 회차는 건축학에서만 진행한다. 텍스처·건축학 각 1장이라는 기본 흐름보다 최신의 좁은 범위를 우선한다. 추가로 5장을 찾으라는 요청은 새 후보 5장을 찾는 것이며, 앞의 후보를 중복해서 세지 않는다.

이번에는 카테고리 피드 안에서 후보를 찾았다. 단어를 입력한 검색을 하지 않았다면 검색했다고 기록하지 않는다. 텍스처 탭에는 추상 그래픽이나 풍경처럼 보이는 이미지도 있으므로 실제 발견한 카테고리를 기준으로 기록한다.

### 단계 C. 모티브에서 조형 특징 추출

1. 소재 이름을 그대로 검색하는 방식과 형태를 추출해 검색하는 방식을 함께 검토한다.
2. 반복·중심축·회전·결속·겹침·경계·굴절·흐림 등 사진에서 실제 보이는 특징을 적는다.
3. 프로필에서 사용할 수 있는 선 장식, 프레임 일부, 패턴, 구분선, 배경 요소 등의 가능성을 생각한다.
4. 모티브를 하나의 그림으로 복제하기보다 남길 특징을 선택한다.

### 단계 D. Pinterest 검색과 추천 탐색

1. Playwright MCP로 Pinterest 탭을 선택한다. 로그인되어 있더라도 저장·팔로우 등의 계정 동작은 이번 작업에 필요하지 않았다.
2. 모티브에서 추출한 소재·형태로 검색한다.
3. 가까운 핀을 연다.
4. 핀 아래 관련 추천을 스크롤하며 더 가까운 조형 언어를 찾는다.
5. 추천 핀을 직접 열어 확인한다. 방향이 멀어지면 이전 핀이나 새 검색으로 돌아간다.
6. 이번 회차에는 키워드별 2개씩 총 10개의 후보를 선정했다. 이는 매 회차의 고정 수량이 아니다. 수업 HTML은 키워드별 서로 다른 콘셉트의 최종 디자인 레퍼런스 1개씩, 총 5개를 제시한다. 사용자가 승인한 이번 조사 수량과 최종 선정 수량을 구별한다.
7. 검색어, 출발 핀 URL, 추천으로 이동한 핀 URL, 선정한 이미지 URL, 연결 이유를 기록한다.

검색 핀과 추천 핀을 각각 반드시 하나씩 채울 필요는 없다. 두 후보를 모두 추천에서 찾거나 여러 단계의 핀을 거쳐도 된다. 중요한 것은 실제로 탐색하고 선택한 이유와 경로를 남기는 것이다. 설명은 에이전트가 직접 쓰며, 핀의 제목이나 자동 설명을 그대로 선정 이유로 대체하지 않는다.

### 모티브와 오너먼트의 대응 기록

- 각 오너먼트가 텍스처 모티브에서 이어졌는지, 건축 모티브에서 이어졌는지, 둘을 결합했는지 적는다.
- `키워드별 2개`가 자동으로 `텍스처용 1개 + 건축용 1개`를 뜻하지 않는다. 이번에는 두 모티브의 공통 특징을 함께 참고한 후보도 있다.
- 서로 다른 후보 2개가 사실상 같은 장식의 변형에 불과하다면 대안을 더 찾아 비교한다.
- 최종 이미지에서 연결이 약하면 먼저 다른 후보를 찾는다. 설명을 정확히 고치는 것은 필요하지만, 이미지와 주제가 맞지 않는데 문장만으로 정당화하지 않는다.
- 한 키워드의 원본 핀을 다른 키워드에도 쓸 수는 있으나, 서로 다른 해석과 적용 이유가 있어야 한다. 수량을 채우기 위한 중복은 피한다.

Pinterest 검색어가 달라도 비슷한 이미지가 반복 추천될 수 있다. 원하는 조형 특징이 나오지 않으면 더 구체적인 말로 바꾼다. 이번 중첩 조사도 `layered contour line ornament`에서 시작했으나 `topographic paper cut abstract`로 구체화했다.

### 단계 E. FigJam에 배치

1. 사용자가 지정한 기존 섹션을 사용한다.
2. 키워드를 같은 순서로 정렬해 모티브와 오너먼트를 대응시킨다.
3. 모티브 섹션에는 출발 취향, 해석, 조형 특징, 사진, 선정 이유, 원본 링크를 넣는다.
4. 오너먼트 섹션에는 조형 특징, 검색어, 추천 탐색 경로, 이미지, 직접 작성한 연결 이유, 원본 링크를 넣는다.
5. 사진은 전체가 보이도록 배치한다. 핵심 윤곽을 임의로 자르지 않는다.
6. 화면을 캡처해서 넣은 한 장짜리 보드 대신, 이미지와 수정 가능한 텍스트를 각각 배치한다.

7. 키워드·이미지·캡션·출처가 한 묶음으로 읽히게 배치한다. 기존 공간에 글자를 억지로 줄이기보다 허용된 영역 안에서 간격과 구성을 조정한다.
8. 기존 색 구분과 5컬럼은 이번 보드의 표현 방식이다. 다음 회차에는 가독성과 연결 관계에 맞춰 도형·연결선·행·열 구성을 선택한다.
9. 마인드맵을 확장할 때는 부모 가지에 실제 연결선을 붙이고 형제 가지의 공간을 확보한다. 원본과 새 연상이 겹쳐 보이지 않게 배치한다.

### 단계 F. 최종 검수와 보고

- 키워드 5개와 이미지 수가 맞는지 확인.
- 모든 이미지가 실제로 업로드되었는지 확인.
- 링크가 각 이미지와 대응하는지 확인.
- 이미지가 화면에 제대로 로딩된 뒤 실제 모습을 확인.
- 설명이 이미지의 실제 구조와 일치하는지 확인.
- 텍스트 겹침, 섹션 바깥으로 넘침, 과도한 잘림을 확인.
- 해석과 객관적 사실을 구별.
- 실제 탐색한 검색어·핀 경로만 기록. 추천 알고리즘이 내부적으로 왜 그 핀을 제안했는지는 단정하지 않음.
- 조사 완료, 사용자가 채택한 후보, 최종 디자인 반영 완료를 각각 구별.
- 완료한 섹션의 직접 링크와 산출물 개수를 사용자에게 간단히 보고.

### 회차별로 남길 상태

`제안 → 조사 → 보드 배치 → 사용자 검토 → 채택 / 보류 / 교체`를 구분한다. 도구 검수가 끝났다는 사실이 사용자의 최종 채택을 의미하지 않는다.

이번 회차 식별: **2026-11-24 · 개인 프로필 1차 키워드 조사 · 모티브 1 / 오너먼트 1**. 도형 마인드맵과 조사 보드는 완료했으며, 후보에 대한 세부 피드백과 최종 선택은 별도다. 기존 강아지 실습은 이 회차의 방법 학습 사례로 연결해 기록한다.

## 10. 도구 사용과 구현 메모

### Playwright MCP

- 사용자는 Playwright MCP가 조작하는 브라우저를 열고 Unsplash와 Pinterest를 직접 열어 두었다.
- 탭 인덱스는 고정값으로 믿지 말고 `browser_tabs`로 확인한다.
- 일반적인 흐름: 탭 확인 → 탭 선택 → 카테고리/검색 이동 → DOM·접근성 정보 확인 → 실제 화면 확인 → 핀 열기 → 추천 스크롤 → 이미지와 출처 확보.
- 이번 조사 당시 Unsplash 탭은 0, Pinterest 탭은 1이었다. 다음 작업 때 달라질 수 있다.
- Pinterest 핀 주소와 이미지 주소를 같은 카드에서 함께 읽는다. 추천 그리드의 순서는 로딩 중 바뀔 수 있다.
- 가능하면 선택한 핀 상세에서 주 이미지의 주소·비율·실제 모습을 확인한다. 추천 카드 목록의 순서와 별도 스크린샷의 위치가 항상 일치한다고 가정하지 않는다.
- Unsplash 이미지는 `figure` 안의 사진 원본 링크와 `img.currentSrc`를 함께 확인했다.
- 계정의 핀 저장, 보드 생성, 게시, 메시지 전송은 수행하지 않았다. 레퍼런스 이미지와 출처를 FigJam에 배치했다.

### Figma MCP

- 쓰기 전에 `figma-use`, `figma-use-figjam` 스킬을 적용한다. 가시적 레이아웃 작업에는 적용 지침에 따라 `figma-generate-design`도 함께 사용했다.
- 새 작업은 `create_session`으로 세션을 만들고 반환받은 세션 ID를 해당 작업의 파일 도구 호출에 사용한다. 이 문서의 과거 작업에 사용한 세션 ID를 새 작업에 임의로 재사용하지 않는다.
- FigJam 구조는 `get_figjam`으로 읽고, 실제 화면은 `get_screenshot`으로 확인한다.
- FigJam에서 `get_metadata`는 사용하지 않는다. Design 전용 도구와 혼동하지 않는다.
- 노드 생성과 일반 수정은 `$fig` 빌더를 사용했다.
- 이미지 슬롯은 사각형, 설명은 별도 텍스트로 구성했다.
- 외부 이미지 삽입은 `upload_assets`를 사용한다. 기존 이미지 슬롯의 `nodeIds`를 넘겨 업로드했다.
- 업로드 URL은 일회용이고 만료된다. 요청한 업로드를 완료한 뒤 다음 묶음을 요청한다.
- 원본 비율을 보존하도록 이미지 채우기는 `FIT`을 사용했다.
- 원본 링크는 텍스트에 실제 하이퍼링크를 부여했다.
- 최종 이미지 채우기 존재 여부, 텍스트 충돌, 섹션 경계 초과를 검사하고 섹션 스크린샷으로 확인했다.

### 파일과 네트워크

- 이번 다운로드 임시 파일: `/private/tmp/profile-keyword-research/` 및 `/private/tmp/dog-ornament-refs/`.
- 임시 파일은 다음 실행에서 없을 수 있다. 영구 자료는 FigJam의 이미지·출처 링크와 이 문서다.
- 이미지 다운로드 및 Figma 업로드 POST는 실행 환경의 네트워크 제한 때문에 승인된 확장 권한으로 수행했다. 다음 작업도 현재 권한 정책을 따르며, 접근 실패를 다른 경로로 우회하지 않는다.
- 이 문서에는 만료되는 업로드 URL이나 인증 정보를 저장하지 않는다.

### HTML의 다음 단계로 넘어갈 때

- 첫인상은 참고 자료로 보고, 본인이 표현하고 싶은 모습 및 좋아함·싫어함과 비교한다.
- 오너먼트 후보를 고른 뒤 필요하면 포스터·배너·편집물 등 실제 적용 사례를 조사한다. 개인 프로필 화면만 검색할 필요는 없다.
- 프로필에 넣을 정보와 문구를 먼저 정하고 제목·소제목·본문·보조 정보의 위계를 잡는다.
- 이미지는 텍스트 가독성과 정보 전달에 맞춰 크기·위치·개수를 조정한다.
- FigJam에서 발상과 조합을 시험하고, Figma에서 타이포그래피·그리드·색상과 시안 5개로 발전시킨다.
- 컬러와 로고는 이후 단계다. 키워드 중 표현하기 쉬운 하나를 로고로 발전시키되, 색의 인상을 절대적 사실로 단정하지 않는다.
- 이 항목은 이후 작업을 위한 순서 기록이며, 현재 시안 제작을 시작하라는 승인으로 해석하지 않는다.
