# 브랜드 리서치 프로젝트 작업 계획

이 프로젝트는 실제 구두 인터뷰를 바탕으로 사용자 경험을 분석하고, 가상인물 인터뷰를 통해 추가 가설을 탐색한 뒤 브랜딩 기획 보고서와 발표 자료를 만드는 작업이다. 가상인물의 답변은 실제 참여자의 발언이나 검증된 조사 결과로 취급하지 않는다.

## 진행 단계

1. 실제 구두 인터뷰 전사문을 정리하고 분석한다.
2. 분석 결과를 바탕으로 가설 페르소나와 추가 질문을 만든다.
3. 가상인물 인터뷰를 진행해 탐색할 가설과 확인 질문을 정리한다.
4. 실제 인터뷰 근거와 검증 전 가설을 구분해 브랜딩을 기획한다.
5. 브랜딩 기획 보고서를 마크다운으로 작성한다.
6. 보고서를 바탕으로 발표용 PPT를 제작한다.

## 예정된 디렉터리 구조

아래 구조는 사용자가 지정한 **예정 구조**다. 하위 디렉터리와 파일은 생성 지시를 받기 전까지 만들지 않는다.

```text
브랜드리서치프로젝트/
├─ 00입력/
│  ├─ 브랜드기초정보.md
│  └─ 인터뷰전사문.txt
├─ 01프롬프트/
│  ├─ 00공통규칙.md
│  ├─ 01인터뷰정리.md
│  ├─ 02가상인물과질문생성.md
│  ├─ 03가상인터뷰진행.md
│  └─ 04브랜딩기획.md
└─ 02결과/
   ├─ 01인터뷰분석.md
   ├─ 02가설페르소나질문지.md
   └─ 03가상인터뷰가설목록.md
```

인터뷰 작업은 위 구조를 기준으로 진행한다. 기획 보고서와 PPT의 구체적인 파일 위치와 이름은 이후 지시에 따른다.

## 구두 인터뷰 분석 원칙

인터뷰는 단순 요약으로 끝내지 않는다. 발언을 근거로 다음 항목을 구분해 정리한다.

| 항목 | 기록 방법 |
| --- | --- |
| 실제 발언 | 전사문 문장을 그대로 인용하고 발언 ID와 시간표시를 붙인다. |
| 상황·행동 | 언제, 어디에서, 무엇을 했는지 발언에서 확인되는 범위만 적는다. |
| 불편·장벽 | 행동을 어렵게 만든 조건을 적는다. |
| 명시적 요구 | 참여자가 직접 원한다고 말한 내용만 적는다. |
| 잠재 니즈 | 분석자의 추론을 `해석`으로 표시하고 근거 발언 ID를 붙인다. |
| 추가 확인 질문 | 현재 자료로 판단할 수 없는 점을 질문으로 남긴다. |

발언에 없는 항목은 억지로 채우지 않는다. 시간 정보가 없으면 임의로 만들지 않고 `시간 미기록`으로 표시한다. 질문자와 참여자의 발언을 구분하고, 참여자가 여러 명이면 익명 ID로 구분한다.

## 분석 순서

1. 전사문의 참여자, 질문·답변, 시간표시 유무와 누락·불명확한 부분을 확인한다.
2. 관련 발언에 ID를 부여하고 원문을 정확히 인용한다.
3. 각 발언의 상황·행동, 불편·장벽, 명시적 요구를 원문과 분리해 적는다.
4. 잠재 니즈를 해석으로 기록하고, 다른 해석이 가능하면 함께 남긴다.
5. 인터뷰 전체에서 반복되는 패턴과 서로 다른 경험·반대 사례를 확인한다.
6. 확인되지 않은 내용은 추가 질문으로 정리한다. 브랜딩 아이디어는 검증 전까지 `가설`로 표시한다.
7. 인용이 전사문과 일치하는지, 분석이 발언보다 강한 결론을 내리지 않았는지 검토한다.

예를 들어 `세척이 귀찮아서 텀블러를 잘 안 들고 다닌다`는 발언은 세척 부담과 사용 행동을 보여준다. 관리 편의성을 강조한 제품이 도움이 될 수 있다는 생각은 브랜드 가설로 남길 수 있지만, 이 발언만으로 구매 의향을 결론내리지 않는다.

## 현재 상태

- 인터뷰 전사문과 브랜드 기초정보는 아직 전달받지 않았다.
- 예정 구조의 하위 디렉터리와 결과 파일은 아직 만들지 않았다.
- 입력 자료를 받은 뒤에도, 파일 생성·작성은 사용자의 지시에 맞춰 진행한다.
